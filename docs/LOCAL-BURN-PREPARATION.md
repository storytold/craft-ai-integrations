# Local Burn weight preparation

The person chooses the graphics-card engine. Setup prepares its model weights once on this
computer, saves them in the shared model cache, and reuses that copy in every app. We do not host
converted weights. The original publisher files stay unchanged and remain usable by rten.

`craft-ai-burn-setup`, feature `conversion`, implements the local preparation step for the exact
SAM 2.1 tiny export already pinned in the catalogue. The runner that reads its output is
`craft-ai-engine-burn` (`docs/BURN-ENGINE.md`). This crate never downloads a model or changes a
connection or binding.

## What ships, and what happens locally

A Burn model has two parts:

1. Its Rust architecture is generated, reviewed and compiled by us when building the engine.
2. The person's original ONNX files are converted to `.bpk` weights on their machine, on demand.

The converter is the bundled `burn-onnx` library. It needs no Cargo, Rust compiler, rustfmt,
Python, installed converter, service, or network call when it runs. Source emitted as a conversion
by-product is discarded, not compiled locally. This supports an architecture shipped with the
engine. It does not let Burn run an arbitrary ONNX graph. A different architecture still needs a
new runner, or an engine such as rten that loads ONNX graphs directly.

The matching compiled runner is `craft-ai-engine-burn`. Its model code is generated by
`tools/burn/generate_sam21.py` from the same pinned `burn-onnx`, with the five code-generation
corrections applied by assertion and split into small files. `REVISION` in `src/sam21.rs` must equal the
script's; a test fails if they differ.

## Host API

```rust,ignore
// On a worker, only after the person chooses this engine and approves setup.
let weights = craft_ai_burn_setup::prepare_sam21(
    original_model_folder,
    shared_burn_cache_folder,
    &cancelled,
)?;
// weights.encoder and weights.decoder identify the complete saved copy.
// Bind only after the host's separate, explicit Use action and executable-runner checks.
```

The cache folder is chosen by the host. It must be outside the original-model folder. Put it in
the shared model area, not an app installation, so other Craft apps reuse it. This slice does not
choose a new global folder policy or migrate existing data.

## Rules

- Only the exact source sizes and SHA-256 hashes supported by the compiled architecture enter
  conversion. Private copies prevent source edits during conversion from changing its input.
- The cache key includes source identity and the converter/architecture revision. Bump the
  revision whenever the architecture, tensor mapping, or converter changes.
- A cross-process file lock prevents two apps preparing the same copy together.
- Only two nonempty, bounded weight files and a bounded manifest are published. Temporary source,
  generated code and failed conversions are cleaned up. If the app is killed in the middle, the next preparation of the same files removes the scratch folders it left (they carry the cache key in their name), and never touches another key's. A final directory appears only after both
  files and the manifest are complete and flushed.
- Reuse checks both saved file hashes. These checks detect changed files, not hostile replacement
  of both a manifest and weights by another process with the same account permissions.
- Damaged saved files are refused, not overwritten or silently repaired. The host can offer an
  explicit removal/rebuild of that derived copy. Originals are never removed or repaired.
- Cancel before starting writes nothing. Cancel during a synchronous converter call takes effect
  when that component finishes, and its late result is discarded. Do not promise immediate Cancel.
- Preparation is not inference, readiness in an app, or permission to bind. Host UI and the generic
  engine registration remain separate work.

## Exercise it

```sh
cargo test -p craft-ai-burn-setup --features conversion -j 8
cargo clippy -p craft-ai-burn-setup --features conversion --all-targets -j 8 -- -D warnings
cargo run -p craft-ai-burn-setup --features conversion --example prepare_sam21 -- <original-folder> <cache-folder>
# Repeat: preparation is Reused, with the same two paths.
# Real conversion test, only with the existing publisher files:
# Set CRAFT_TEST_SAM21_ONNX_DIR, then:
cargo test -p craft-ai-burn-setup --features conversion -j 8 -- --ignored
python tools/mutation/mutation_check.py bp
```

Evidence on Windows, 21/10/2026: real files converted and then reused by a standalone executable
with PATH empty and developer-tool locations absent. The saved weights ran through the existing
release Burn/wgpu spike and produced best-mask IoU 1.0 against the stored ONNX Runtime reference
for one image and one click. This is a model/weight proof, not an app, launcher, other-OS, or
production-engine integration test. Timing from the debug setup probe is not a release benchmark.
